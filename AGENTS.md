# Для агентов

С Chimera работают через команду `chimera` (в папке программы это `Chimera.exe`).

1. `chimera agent-info --json` — версии программы и протокола, команды с уровнями, пути, совместимая версия скилла.
2. `chimera docs` — документация именно этой версии программы (темы: команды, папки и файлы, формат вывода); справка по команде: `chimera <команда> --help`.
3. Правила поведения — порядок действий, безопасность, что делать при несовпадении версий: `skills/chimera/SKILL.md`.

Если команды `chimera` нет или она старее скилла, ничего не запускайте в обход неё и сообщите пользователю. Изменения системы (hosts, DNS, TUN, запуск обхода, обновление) — только по прямой просьбе пользователя. Ссылки прокси и секреты не показывать.

Списки `lists/*.txt` можно править напрямую: работающая Chimera (окно, трей или служба) подхватывает правку сама за пару секунд, как `lists save`. Проверка: `chimera lists validate`; результат применения — последняя строка `data/changes.log` (источник `file`, `ok` или `error`). Не править вручную: `config.json` и `data/*.json` (на лету не подхватываются, для них есть команды), `strategies/hostlists/list-general-user.txt`, `strategies/hostlists/ipset-user.txt`, `data/singbox-*.json`, `data/proxy.pac`, `data/control.json`, логи.

Для человека в терминале: `chimera tui` — полноэкранный интерфейс (клиент работающей Chimera), `chimera tui --simple` — простое меню; агентам он не нужен, работайте командами.

Для разработки репозитория: `docs/CLI.md`, тесты — `python -m pytest`, что чем проверяется и как писать новые — `docs/TESTING.md`. Для разработки интерфейса нужен Node 22+: исходники нового фронта в `frontend/`, устройство — `docs/FRONTEND.md`.
