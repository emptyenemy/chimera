# Языки программы

Сейчас два языка: русский и английский. Запасной язык — английский. Этот файл описывает
устройство (для тех, кто добавляет тексты), контракт для окна и границы перевода.

## Как выбирается язык

Приоритет сверху вниз:

1. флаг `--lang ru|en` (только для команды `chimera`, действует на один запуск);
2. переменная окружения `CHIMERA_LANG` (`ru`, `en`, `auto`);
3. ключ `lang` в `config.json`: `auto` (по умолчанию), `ru` или `en`;
4. `auto`: язык интерфейса Windows (`GetUserDefaultUILanguage`). Русский, украинский и
   белорусский дают `ru`, всё остальное `en`. Если определить не удалось — `ru`.

Менять язык: `chimera lang set en` (или `config set lang en`, или окно через `config_set`).
Посмотреть: `chimera lang show`.

## Каталоги

`modules/locales/ru.json` и `en.json` — плоские словари «ключ: текст», ключи отсортированы.
Сборка (`build.bat`) кладёт папку рядом с программой.

- `{имя}` в тексте подставляется из параметров; порядок слов остаётся за переводчиком.
  Неизвестный параметр остаётся в тексте как есть.
- Множественное число — набор ключей `ключ.one|few|many|other` и параметр `count`.
  Обязательные формы: ru — `one`, `few`, `many`; en — `one`, `other`. Выбор формы: ru —
  1, 21, 101 → `one`; 2–4, 22–24 → `few`; 0, 5–20, 25 → `many` (11–14 всегда `many`);
  дробные → `other`, а если её нет — `many`. en: 1 → `one`, остальное `other`. Правила те же,
  что у `Intl.PluralRules`; образцы чисел для сверки отдаёт `i18n_get` (`plural.<язык>.samples`).
- Ключа нет в языке — берётся английский; нет и там — возвращается сам ключ. Программа не
  падает, а пропуск ловят тесты (`tests/test_i18n_catalog.py`).
- Русский и английский обязаны иметь одни и те же ключи (формы множественного числа у языков
  разные) и одни и те же имена `{параметров}`. Английский без кириллицы.

Именование ключей:

| Префикс | Что |
|---|---|
| `err.*` | ошибки (`ChimeraError`); код ошибки = ключ |
| `cli.*` | командная строка: `cli.cmd.<группа>[.<действие>].summary/.ui/.arg.<параметр>`, `cli.group.*`, `cli.level.*`, `cli.excluded.*`, `cli.argname.*`, `cli.help.*`, `cli.usage.*`, `cli.err.*`, `cli.msg.*` и т. д. |
| `docs.*` | `chimera docs`, `agent-info`, `docs/CLI.md` |
| `doctor.*` | диагностика: `doctor.<id>.title`, `doctor.<id>.<вариант>.message/.hint` |
| `tray.*` | меню и уведомления трея |
| `tui.*` | терминальный интерфейс |
| `msg.*` | сообщения менеджеров и результаты операций |

Добавить текст: вписать ключ в оба файла (по алфавиту), в коде `t("ключ", имя=значение)`
или `ChimeraError("err.…", имя=значение)`. Ключи, которые код собирает из таблиц (команды,
раскладка папок), проверяют тесты по самим таблицам.

## Ошибки

`modules/errors.py`: `ChimeraError(code, **params)`. `code` — ключ `err.*` из каталога, только
литералом (это проверяет тест). `str(e)` даёт русский текст, `e.message(lang)` — текст на языке.
`ChimeraValueError`, `ChimeraRuntimeError`, `ChimeraOSError`, `ChimeraPermissionError`,
`ChimeraFileNotFoundError` и `ChimeraKeyError` сохраняют соответствующий стандартный тип
исключения, чтобы существующие обработчики продолжали работать.

Ответ `Api` при ошибке:

```json
{"ok": false, "error": "Только http(s)-ссылки", "code": "err.url.http_only", "params": {}}
```

- `error` — русский текст, как раньше: старое окно и агенты продолжают работать.
- `code` — ключ каталога; окно берёт `t(code, params)` на своём языке.
- `code == "err.raw"` — системное или внешнее исключение без каталожного кода; исходный
  текст сохраняется в `params.message` и в `error`.
- То же есть в шагах «Выключить всё» (`data.steps[i]`) и в `apply_error_code` /
  `apply_error_params` рядом с `apply_error` у `game_filter_set`, `fake_set`, `tg_set_advanced`.

`--json` у `chimera`: в объекте `error` добавлены `key` и `params` (ключ сообщения и его
параметры; есть у ошибок, созданных программой). Существующие `code` (`usage`,
`not_running`, `remote_error`, …) не менялись, `schema` остаётся 1: поля только добавлены.
Текст `message` зависит от языка, `code` и `key` — нет.

## Контракт для окна

- `lang_get()` → `{setting, lang, system, available}`: что выбрано (`auto|ru|en`), что из
  этого получилось, язык системы.
- `config_set("lang", "auto" | "ru" | "en")` — смена языка; после неё окно заново берёт каталог.
- `i18n_get(lang?)` → `{lang, fallback, langs, catalog, plural}`. `catalog` — весь каталог
  языка поверх английского (недостающие ключи уже добраны). Без `lang` — текущий.
  `plural.<язык>` — `{categories, samples}`.
- Выбор формы для ключа `k` и числа `n`: `cat = Intl.PluralRules(lang).select(n)`; ищем
  `k.cat`, затем `k.other` (для `cat == "other"` — затем `k.many`), затем `k`.
- Проверка диагностики: каждый элемент `checks` имеет `code` и `params`; заголовок —
  `doctor.<id>.title`, текст — `<code>.message`, подсказка — `<code>.hint` (если ключ есть).
- Метка «в интерфейсе» у команд (`cli.cmd.*.ui`) описывает подписи окна; при смене подписей
  окна правится и она.

## CLI и документация

- Справка, сообщения, `chimera docs`, `agent-info` идут из каталога. `--json` не меняет
  идентификаторы (команды, уровни, имена параметров, коды), переводятся только тексты.
- Русские имена позиционных параметров (`стратегия`, `имя`) — стабильные идентификаторы в
  `--json` (`args[].name`); показываемое имя — `args[].label`.
- `python tools/gen_cli_docs.py` пишет `docs/CLI.md` (ru) и `docs/en/CLI.md` (en);
  `--lang en` — только английский, `--check` — проверка актуальности. Тесты сверяют оба файла.

## Тесты

- `tests/test_i18n.py` — выбор языка (подмена `ctypes`), подстановка, множественные формы
  (ru 1/2/5/11/21/101, en), запасной язык, ошибки с кодом, `lang` в `config.json`.
- `tests/test_i18n_catalog.py` — равенство ключей и параметров ru/en, полнота форм,
  неопределённые и неиспользуемые ключи, коды `raise ChimeraError` только из каталога.
- `tests/test_cli_i18n.py`, `tests/test_doctor_i18n.py`, `tests/test_api_i18n.py`,
  `tests/test_tray_model.py` — слои.
- `tests/conftest.py` выставляет `CHIMERA_LANG=ru`: остальные тесты сверяют русские тексты.

## Что не переводится

- Логи (`data/logs`, `applog`, журнал изменений): русские, как читает разработчик и как их
  присылают в issue.
- Сообщения консольных инструментов разработчика (`tools/`).
- Русские алиасы `да`/`нет` у `on|off` в командах остаются как ввод.

## Менеджеры и терминальный интерфейс

Исключения менеджеров используют коды каталога. Для совместимости с прежними обработчиками есть `ChimeraValueError`, `ChimeraRuntimeError`, `ChimeraOSError`, `ChimeraPermissionError`, `ChimeraFileNotFoundError` и `ChimeraKeyError`: они сохраняют стандартный тип исключения и добавляют `code`/`params`.

Сообщения валидации списков, предпросмотра и импорта конфигов, проверки доступности, источников и канала команд идут через `msg.*`. Названия разделов обмена конфигами и источников вычисляются при чтении, поэтому следуют текущему языку. Исключения сторонних библиотек и системные ошибки остаются `err.raw` с исходным текстом.

Полноэкранный Textual и простое меню используют `tui.*`. Язык процесса выбирается `--lang` или настройкой программы; в Настройках TUI можно менять `lang` работающей Chimera. В сборке Textual проверяется в headless-режиме: загрузка зависимостей, девять вкладок, связь с API и отрисовка SVG.

Английская документация: `README.en.md`, `docs/en/CLI.md`; сайт — `landing/en/index.html`, общие стили и скрипты с русской страницей. Логи и скрипты разработчика остаются на русском.

## Интерфейс

Все девять страниц используют `frontend/src/locales/ru.json` и `en.json`. В Настройках доступен выбор auto/ru/en на лету; `lib/language.ts` слушает `langChanged`, загружает каталог бэкенда, ошибки выбирает по коду. Каталоги интерфейса, параметры и формы множественного числа проверяет `npm test`.
