# Релизы и обновления

Как Chimera собирается, выкладывается и обновляется у пользователей.

## Коротко

- Пользователь качает zip со страницы Releases, распаковывает, запускает `Chimera.exe`. Python и git ему не нужны.
- Релиз выпускается тегом: `git tag v0.2.0 && git push origin v0.2.0`. Остальное делает GitHub Actions.
- Тег с дефисом (`v0.3.0-beta.1`) публикуется как пре-релиз — его видят только те, кто выбрал бета-канал.
- Программа сама проверяет, вышла ли новая версия, а ставит её только по кнопке.

## Версия

- Единственный источник — `modules/version.py` (`VERSION`). В репозитории там `dev`: запуск из исходников — это всегда «разработческая» версия, и самообновление в ней выключено.
- В сборке CI подставляет версию из тега (`v0.2.0` → `0.2.0`). Руками в файле ничего не меняется.
- Сравнение — по semver: `0.3.0-beta.1 < 0.3.0-beta.2 < 0.3.0`.
- В свойствах exe (FileVersion) — числовая часть версии: `0.3.0-beta.1` → `0.3.0.1`, `0.3.0` → `0.3.0.0`.

## Сборка (`build.bat`)

- Nuitka standalone, exe — `Chimera.exe`, папка сборки — `build\Chimera\`, иконка — `assets/logo/chimera.ico`.
- Бинарники готовит `tools/fetch_bins.py` — и в CI, и локально:
  - sing-box — пиннутая версия из `modules/proxy/manager.py`, со сверкой SHA256;
  - zapret-win-bundle — на пиннутом коммите, в сборку идёт только `zapret-winws/` (4 МБ из 62: остальное — cygwin/blockcheck, программа их не использует).
- При сборке пишется `versions.json` — версии сабмодулей, бандла и sing-box. В собранной программе git нет, и «Источники и обновления» берут версии оттуда, а не показывают «—».
- Сабмодули в `upstream/` (стратегии Flowseal, zapret2, tg-ws-proxy) в сборке уже внутри: стратегии — перепортированными `strategies/*.txt`, ядро tg-ws-proxy — пакетом.

## GitHub Actions

`.github/workflows/release.yml` — только на пуш тега `v*`, `windows-latest`:

1. checkout с сабмодулями;
2. Python 3.14, `pip install -r requirements-dev.txt`;
3. `pytest`;
4. `tools/fetch_bins.py`;
5. версия из тега → `modules/version.py`;
6. `build.bat`;
7. zip `Chimera-<версия>-win64.zip` (внутри папка `Chimera/`);
8. релиз с архивом; тег с дефисом — пре-релиз. Текст — автоматический список изменений от GitHub, его можно отредактировать после.

`.github/workflows/ci.yml` — на pull request и пуш в `main`: `ruff check` и `pytest` на `windows-latest`, без сборки. Нужен, чтобы чужие PR проверялись до мержа.

Ветка одна — `main`. Бета — это тег на любом коммите, отдельная ветка под неё не нужна.

## Самообновление (`modules/selfupdate.py`)

### Проверка

- При запуске и раз в 6 часов (выключается в настройках), плюс кнопка «Проверить».
- Стабильный канал — `GET /repos/emptyenemy/chimera/releases/latest`; бета — список релизов, берётся самая свежая версия, пре-релизы включительно.
- В релизе ищется ассет `Chimera-*-win64.zip`; SHA256 берётся из поля `digest` ассета.
- Без токена. Пока репозиторий приватный, GitHub отвечает 404 — программа пишет «не удалось проверить», а не падает.
- Нашлась новая версия — одно уведомление и отметка у версии в шапке сайдбара.

### Установка — только по кнопке

1. «Обновить до X» → архив качается в `data/update/` с прогрессом, SHA256 сверяется, архив распаковывается во временную папку.
2. Программа гасит свои процессы (winws2, sing-box), останавливает фоновую службу, если она запущена, запускает `data/update/apply.cmd` отдельным процессом и завершается.
3. Скрипт:
   - ждёт, пока процесс Chimera закроется;
   - копирует текущую версию в `data/update/rollback/`;
   - `robocopy /MIR` новой версии поверх папки программы;
   - при ошибке копирования возвращает версию из `rollback/`;
   - поднимает службу обратно, если она работала, и запускает `Chimera.exe`;
   - пишет всё в `data/logs/update.log`.
4. Не трогаются: `data/`, `config.json`, пользовательские хостлисты (`strategies/hostlists/list-general-user.txt`, `ipset-user.txt`, `ipset-all.txt` и его `.backup`).

### Интерфейс

- «Настройки → Источники и обновления»: строка «Chimera» (текущая версия, свежая, кнопка), канал «Стабильный / Бета», переключатель «Проверять обновления».
- В запуске из исходников строка показывает, есть ли новая версия, но кнопка неактивна с подсказкой «обновляется через git».

## Что поправить заодно

`modules/autostart.py` и `modules/service.py` отличают exe от исходников по `sys.frozen`, а Nuitka этот флаг не ставит: в сборке задача Планировщика запускала бы `pythonw main.py`. Проверять так же, как `main.py` и `modules/paths.py`, — ещё и по `__compiled__`.

## Проверка

- Юнит-тесты: сравнение версий (включая пре-релизы), разбор ответа GitHub и выбор ассета по каналу, сверка SHA256, генерация `apply.cmd` со списком исключений.
- Сам `apply.cmd` прогоняется на фейковых папках во временном каталоге: копирование, исключения, откат при ошибке.
- UI — безголовыми скриншотами с моком; окно программы при проверке не запускается.
- Сборку целиком проверит первый тег; до него — `build.bat` локально.
