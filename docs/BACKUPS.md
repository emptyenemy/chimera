# Бэкапы и восстановление

Ручной снимок сохраняет все поддерживаемые настройки Chimera и пользовательские
списки. Перед изменениями через окно и CLI автоматически сохраняются затрагиваемые
настройки и списки, в том числе перед импортом и восстановлением. Это настройки программы, а не образ компьютера.
Хранится до десяти обычных снимков в `data/backups/` и отдельно закреплённый проверенный снимок.

Сохраняются настройки программы, стратегии и IPSet, прокси и Telegram-прокси,
пользовательские провайдеры DNS, привязки hosts и списки. Состояние задач автозапуска
и текущие DNS сетевых адаптеров Windows в снимок не входят.

## В окне

**Настройки → Инструменты → Бэкапы настроек.**

«Создать снимок» сохраняет текущее состояние без изменения работающих модулей.
«Открыть бэкапы» показывает ручные снимки, автоснимки «Перед изменением»
и копии перед импортом/восстановлением.

1. Выберите снимок и откройте предпросмотр.
2. Проверьте разделы и изменения. Повреждённый снимок применить нельзя.
3. Нажмите «Восстановить». Сначала сохраняется текущее состояние, затем применяются
   настройки снимка. При ошибке программа пытается вернуть состояние до восстановления
   и показывает результат отката.

Изменения применяются через менеджеры программы к работающим модулям. Остановленные
модули восстановление само не запускает. Параметры режима запуска и движка окна
вступают в силу при следующем запуске.

## Последняя проверенная конфигурация

В исходниках следующего обновления: **Настройки → Инструменты → Бэкапы настроек →
Проверить сайты**. Укажите от одного до шести доменов, важных для своей задачи.
С текущими настройками подключения выполняются параллельные HTTPS-проверки;
PAC проверяется через локальный SOCKS5 для доменов, направленных в прокси.

Если каждый сайт отвечает HTTP 2xx/3xx, сохраняется полный снимок настроек и списков
с датой и перечнем проверенных сайтов. Он закреплён: обычные автоснимки его не
вытесняют. Следующая успешная проверка заменяет закреплённый снимок; прежний остаётся
в обычной истории до очистки по лимиту. Ошибка, таймаут или проверка браузера
(Cloudflare challenge) не считаются подтверждённой доступностью и не заменяют снимок.
Если настройки, списки или работающие модули изменились во время проверки,
потребуется повторить её. Незавершённая проба настроек блокирует проверку.

**«Вернуть как работало»** открывает обычный предпросмотр сохранённого снимка.
Применение требует отдельного нажатия «Восстановить» и сохраняет текущее состояние
для отмены. В истории снимок помечен «Проверенный». Повреждённый или отсутствующий
снимок не предлагается для восстановления; можно проверить сайты и сохранить новый.

Снимок покрывает настройки Chimera и списки. Он не сохраняет системный DNS адаптера,
состояние сети, текущий системный hosts и включённость процессов. Остановленные
модули после восстановления нужно включить самостоятельно. HTTP-проверка не
гарантирует скорость, вход в аккаунт или все функции сайта; на другой сети условия
могут измениться. В TUI эти действия находятся в разделе «Настройки»: поле доменов,
Enter или «Проверить и сохранить», затем «Вернуть как работало» с предпросмотром
и подтверждением. Стрелки/WASD и клавиатурное меню сохраняются.

```powershell
chimera config verify youtube.com,discord.com --json
chimera config verified --json
chimera config restore-preview <id-проверенного-снимка>
chimera config restore <id-проверенного-снимка> --confirm
```

`verify` сохраняет локальный снимок, не меняя системные настройки и не запуская
модули. Неуспешная проверка возвращает код 1 и результаты по каждому домену.
`verified` только читает. При работающей службе проверку и снимок выполняет служба.
Метаданные проверки и ответы CLI не содержат ссылок прокси и секретов.

Проверка разработки без изменения системы:

```powershell
python -m pytest tests/test_verifiedconfig.py tests/test_verified_tui.py
python tools/smoke_verified_config.py --screenshot verified.png
```

## Через CLI

```powershell
chimera config backup
chimera config backups
chimera config restore-preview 20260930-120000-001-import
chimera config restore 20260930-120000-001-import --confirm
```

`--json` доступен у всех команд. `backup` сохраняет локальный снимок; `backups`
и `restore-preview` только читают. Восстановление требует явного `--confirm`. Если применяемые настройки затрагивают системные инструменты,
понадобятся права администратора. Команда работает и через фоновую службу.

## Совместимость снимков

- Ручной снимок хранит полный набор списков. При восстановлении удаляются списки,
  появившиеся после снимка. Предпросмотр показывает их удаление; снимок перед
  восстановлением позволяет вернуть их обратно.

- Старые папки `*-import` поддерживаются. В них были только копии существовавших файлов:
  какие списки появились после импорта, они не фиксировали. Поэтому восстановление такого
  снимка возвращает сохранённые настройки и списки, но не обещает удалить новые списки.
  IPSet стратегий в старых снимках также не сохранялся. Эти ограничения показываются
  в предпросмотре.
- Новые снимки содержат манифест, хеши файлов и отметки об отсутствовавших списках.
  Восстановление удаляет списки, созданные соответствующим импортом, и возвращает
  зависимые настройки и сохранённый IPSet стратегий. Снимок перед восстановлением
  позволяет отменить это действие.
- Локальные бэкапы содержат сохранённые ссылки прокси и секреты. Предпросмотр и вывод CLI
  показывают только факт их изменения. Для передачи настроек друзьям предназначен экспорт
  `.chimera`, который исключает эти секреты.

## Сравнение снимков

В списке бэкапов выберите два снимка и нажмите «Сравнить снимки». Порядок выбора
определяет направление: первый → второй. В CLI:

```powershell
chimera config compare <первый-id> <второй-id> --json
```

Сравнение только читает сохранённые данные, работает без прав администратора и не
зависит от текущих настроек или доступности прежней стратегии. Показывает изменённые
поля, добавление/удаление/изменение списков и провайдеров. Ссылки прокси, адрес
Telegram-прокси, секреты и содержимое списков не выводятся.

Раздел или список, которого нет в частичном снимке, помечается «не сохранён»:
это неизвестное состояние, а не удаление. Полный снимок фиксирует весь набор списков,
включая пустой. «Сохранённые данные совпадают» относится к данным этих снимков.

## Автоснимки перед изменениями

Добавлены в исходники для 1.0.2 вместе с ручными снимками и сравнением.

| Изменение через окно или CLI | Что сохраняется до записи |
| --- | --- |
| Настройки программы, язык, тема, DNS-пробы, игровой фильтр | Настройки программы |
| Режим IPSet и обновление его содержимого | IPSet и резерв содержимого |
| Настройки прокси и Telegram, смена секрета | Настройки соответствующего модуля |
| Списки и автозапуск winws, выбор стратегии при запуске | winws, настройки программы и IPSet |
| Привязки hosts, общий выключатель и фоновая проверка | hosts и пользовательские провайдеры |
| Добавление/удаление провайдера DNS или hosts | Провайдеры и привязки hosts |
| Сохранение/создание списка | Старое содержимое либо отметка об отсутствии |
| Удаление/переименование списка | Списки и связанные настройки прокси, winws и hosts |

При закрытой Chimera команды изменения настроек, языка и списков тоже создают
автоснимок. При работающей службе снимок и изменение выполняются владельцем службы.

Снимок записывается и проверяется **до** изменения. Если сохранить его не удалось,
изменение не выполняется. Сохранение того же значения и отклонённая операция без
изменений убирают временный снимок, сохраняя прежнюю историю. При частичной ошибке
снимок остаётся для восстановления. Импорт и восстановление создают один снимок
на всю операцию, без дополнительных копий для каждого внутреннего setter.

Автоснимок частичный: возвращает затронутые настройки, сохраняя остальные текущими.
Чтение, обычный запуск/остановка процессов, прямые правки файлов списков, замена
бинарных fake-файлов стратегии, системный DNS адаптера и задачи автозапуска Windows
автоснимками не покрываются. Выбор стратегии при `winws start` сохраняется, поскольку
он меняет настройки winws. Для полного состояния программы есть ручной снимок.
