# Автонастройка

Chimera сама проверяет с компьютера пользователя, какие сервисы недоступны, перебирает
способы обхода и оставляет тот, при котором сервис открывается. Пользователю не нужно
знать, чем стратегия отличается от hosts-провайдера.

В окне — страница «Автонастройка»: «Настроить всё» для всех недоступных сервисов,
«Починить» у отдельного сервиса и «Проверить» без изменений. В терминале — `chimera fix`.

## Что такое сервис

Сервис — это список из `lists/` (youtube, discord, openai…). Для проверки берутся
до трёх адресов списка: для встроенных — заранее выбранные (`modules/autotune/targets.py`),
для своих списков — первые домены. Берутся только точные записи списка: hosts-подмена
работает лишь для перечисленных имён, без поддоменов.

Каждая проверка — та же, что на странице «Проверка»: системный DNS, TCP, TLS с настоящим
SNI и HTTP-запрос, через тот маршрут, которым сайт идёт сейчас (выборочный прокси
учитывается). Страница дочитывается до 64 КБ: ТСПУ пропускает хендшейк и первые 14–25 КБ,
а потом замораживает соединение с хостингами и CDN, и браузер грузит такой сайт бесконечно.
Результат адреса — «открывается», «блок DPI» (сброс или таймаут на TLS, заморозка посреди
передачи), «нет DNS», «отказ по стране» (HTTP 403/451) или ошибка. Время «открывается»
включает загрузку этих килобайт, поэтому умный режим сравнивает варианты по скорости
загрузки, а не по одному рукопожатию.

## Порядок перебора

Диагноз решает, что вообще пробовать, а порядок — от самого безобидного к самому тяжёлому:

| Шаг | Что пробуется | Когда | Что затрагивает |
|---|---|---|---|
| 1. Стратегии | все стратегии winws2, запомненная для этой сети — первой | есть блок DPI или ошибка | только домены выбранных списков |
| 2. Hosts | провайдеры с разблокировкой (xbox, comss, malw…) для списка сервиса | сервис всё ещё недоступен | только имена из списка |
| 3. DNS | системный DNS активного адаптера: обычные провайдеры при «нет DNS», разблокирующие при отказе по стране | сервис всё ещё недоступен | весь компьютер |
| 4. Прокси | добавить список в прокси и запустить его | только если ссылка прокси уже задана | трафик сервиса через сервер пользователя |

Стратегия одна на всю систему, поэтому «Настроить всё» ищет стратегию, которая чинит
больше всего сервисов сразу. Hosts назначается каждому списку отдельно. DNS тоже один
на систему: его вариант принимается, только если не ломает ничего из того, что работало.

Сервис с отказом по стране стратегиями не лечится — для него шаг 1 пропускается.
Если ничего не помогло, отчёт говорит, чего не хватает: «нужен прокси» при отказе по
стране, «проверьте подключение» при общем сбое.

## Быстрый и умный режим

- **Быстрый** — на каждом шаге принимается первый вариант, при котором открылись все адреса.
  Обычно это десятки секунд.
- **Умный** — проверяются все варианты шага. Лучший — тот, при котором открылось больше
  сервисов и адресов, а при равенстве — с меньшей медианной задержкой за три прохода.
  Это минуты.

Задержка — время TCP+TLS и ответа сайта, а не скорость скачивания. Замер скорости
видео и загрузок — отдельный пункт [ROADMAP](ROADMAP.md).

## Что не должно сломаться

- **Контрольные сайты.** Вместе с сервисами каждый раз проверяются `ya.ru`, `example.com` и
  `microsoft.com` — из разных сетей, чтобы контроль работал и там, где `ya.ru` заблокирован
  (Украина) или режут Cloudflare. Вариант, при котором перестал открываться контрольный сайт,
  который открывался до начала, отбрасывается: интернет у пользователя не пропадёт.
- **Работающие сервисы.** Вариант, при котором перестал открываться сервис, который
  работал до начала, тоже отбрасывается.
- **Откат.** Перед началом сохраняется точное состояние: запущенная стратегия и её списки,
  блок hosts и привязки, режим, списки и запуск прокси, DNS активного адаптера. Плюс
  обычный снимок в истории бэкапов. «Отменить» во время подбора и «Вернуть как было»
  после него возвращают всё одним действием.
- **Авария.** Запись сессии лежит в `data/autotune.json`. Если программа закрылась
  посреди подбора, при следующем запуске владелец модулей возвращает исходное состояние.
- **Одна операция за раз.** Пока идёт подбор, другие изменения настроек и пробы
  блокируются. «Выключить всё» доступно всегда и прерывает подбор.
- **Чужие процессы** (winws или sing-box, запущенные не Chimera) не трогаются:
  соответствующий шаг пропускается с пояснением.

Нужны права администратора: стратегии, hosts и DNS меняют систему.

## Память сети

Удачный вариант запоминается для текущей сети (`data/autotune-memory.json`): ключ —
адаптер и его подсеть. В следующий раз в той же сети этот вариант пробуется первым,
и быстрый режим обычно заканчивается на первой попытке. Совпадение ключа у разных
сетей безвредно: запомненный вариант просто проверяется первым.

## Карта провайдеров

После запомненного для сети идут варианты, которые сработали у других пользователей того же
провайдера, потом все остальные. Карта меняет только порядок: перебор и проверки те же.

- **Откуда.** Кнопка «Поделиться результатом» на итоге (или `chimera fix report`) открывает
  на GitHub форму обсуждения (Discussions) с готовым отчётом: номер сети провайдера, что было
  с каждым сервисом и
  чем его починили. Адресов, доменов и ссылок в отчёте нет, публикует его сам человек.
  `tools/provider_map.py` собирает из обсуждений категории отчётов файл
  `strategies/provider-map.json`: каждый автор считается один раз на провайдера, в карту идут
  только встроенные сервисы. Карта приходит пользователям с обновлением данных.
- **Провайдер** — номер сети (AS) по данным RIPEstat, открытого сервиса реестра RIPE NCC.
  Его спрашивают, только когда в карте есть провайдеры или по кнопке отчёта, раз на сеть: ответ
  хранится в памяти сети. Пока полный TUN прокси несёт весь трафик, не спрашивают вовсе:
  RIPEstat увидел бы сервер прокси.

## Самолечение в фоне

Переключатель «Чинить автоматически» на странице (или `chimera config set autotune_watch true`).
Раз в 15 минут Chimera проверяет сервисы, которые автонастройка уже чинила в этой сети, —
тем же диагнозом, что «Проверить», ничего не меняя. Сервис, который не открылся две проверки
подряд при живом интернете, получает быстрый подбор только для себя. Одна неудача — не повод:
сайт мог моргнуть. Без интернета счёт начинается заново. Пока идёт подбор, проба или не закрыта
прошлая сессия, наблюдатель ждёт. Итог виден на странице с пометкой «сработала сама» и кнопкой
«Вернуть как было», а значок в трее показывает уведомление: что и чем починено или что
не открылось. Окно в это время обычно закрыто, а подбор меняет систему — об этом надо знать.

По умолчанию выключено. Подбор меняет систему, поэтому нужны права администратора: окно,
запущенное без них, только запишет в журнал, что не смогло начать. Под службой права есть всегда.
Устройство — `modules/autotune/watch.py`, тесты — `tests/test_autotune_watch.py`.

## CLI

```powershell
chimera fix check                 # диагноз всех сервисов, ничего не меняет
chimera fix check youtube discord
chimera fix                       # настроить всё недоступное, быстрый режим
chimera fix youtube --smart       # починить один сервис, умный режим
chimera fix status --json
chimera fix cancel                # прервать подбор и вернуть как было
chimera fix revert                # вернуть состояние до последней автонастройки
chimera fix keep                  # оставить результат и забыть исходное состояние
chimera fix services              # сервисы и их проверочные адреса
chimera fix report                # отчёт для обсуждений: что сработало у вашего провайдера
```

`chimera fix` ждёт окончания и печатает ход подбора; `--json` — итоговое состояние.

В `chimera tui` автонастройка — экран по Ctrl+F или из «Обзора»: те же действия и те же тексты,
ход подбора виден и в главном меню (`tui/autotune.py`).

## Устройство

| Что | Где |
|---|---|
| проверочные адреса и контрольные сайты | `modules/autotune/targets.py` (у `cloudflare` — его же сайты на тех же сетях) |
| алгоритм: диагноз, шаги, выбор, отчёт | `modules/autotune/engine.py` |
| сессия: поток, отмена, откат, запись на диск | `modules/autotune/manager.py` |
| память сетей | `modules/autotune/memory.py` |
| провайдер (RIPEstat) и карта провайдеров | `modules/autotune/provider.py`, `strategies/provider-map.json` |
| отчёт для обсуждений | `modules/autotune/report.py`, сборка карты — `tools/provider_map.py` |
| операции над модулями и проверка | `ui/autotune.py` (`AutotuneOps`) |
| методы окна | `ui/api.py`: `autotune_state`, `autotune_catalog`, `autotune_diagnose`, `autotune_start`, `autotune_cancel`, `autotune_revert`, `autotune_keep`, `autotune_share`; источник хаба `autotune` |
| интерфейс | `frontend/src/pages/autotune.tsx` |

Алгоритм не знает про Windows: он получает операции (`apply_strategy`, `assign_hosts`,
`apply_dns`, `apply_proxy`, `check`…) и тестируется на модели сети
(`tests/test_autotune_engine.py`). Живой интерфейс — `tools/smoke_autotune.py` с той же моделью.

## Чего автонастройка не делает

- Не достаёт прокси: сервер — только пользователя.
- Не меряет скорость скачивания (см. ROADMAP «Качество подключения»).
